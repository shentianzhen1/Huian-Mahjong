# 惠安窗口采集验证器 V0.1

项目根目录双击 **START_CAPTURE_VALIDATOR.bat**。本机已经建立 `.venv-capture` 并安装依赖。
其他电脑可用 Python 3.12 64 位运行 INSTALL_CAPTURE_VALIDATOR.bat；保留原有 Python 即可。
启动失败会保留错误窗口，不会自动下载软件或切换截图后端。

## 使用

1. 在微信打开开心麻将独立窗口，保持窗口未最小化。
2. 验证器刷新窗口列表，选择正确标题和 PID；相同标题可用 HWND 区分。
3. 默认选 WGC，点击开始预览。检查是不是目标窗口以及画面是否跟随游戏变化。
4. 保存截图得到 PNG＋JSON；短录屏默认 30 秒，可设 1–120 秒，得到 AVI＋JSON＋逐帧 JSONL。
5. 文件在项目根目录 `data/capture_validation/`，每次独立命名，不覆盖已有证据。

只采集画面，不读游戏内存、不发网络请求、不进行游戏点击、不识别牌型、不修改 Rules。
截图／视频可能包含昵称等可见信息，均留在本地；程序没有上传功能。

## 三种后端

| 后端 | 用途 | 限制 |
|---|---|---|
| WGC | Windows Graphics Capture；精确 HWND 目标 | 需 Windows 支持；实际微信版本能否正常捕获要在本机验证 |
| PrintWindow | 与 legacy 截图路线对照 | 加速渲染窗口可能黑屏／旧帧／卡住；隔离进程避免卡住主界面 |
| 屏幕区域 | 根据窗口当前位置截取桌面矩形 | 会把覆盖在目标上的其他窗口一起录入，不是后台捕获 |

三种后端不保证相同边框裁剪，切换后应分别校准。采集按约 10 FPS 限流。
WGC 可能只在内容变化时产生新帧，因此“无新帧／无变化”不能证明游戏卡住。
界面会将静止与停帧写为待区分情况，不能把这一提示用于自动点击决策。

## 异常处理

- 窗口关闭／最小化或 PID 不匹配：停止采集与录屏，需要恢复后重新开始。
- 疑似黑屏：提示并停止录像；不自动改为截取桌面。
- 超过 3 秒无新帧：保留最后预览但明确提示其状态，停止录像并禁止保存旧截图。
  静态 WGC 画面也可能触发此保护；让目标产生可见变化再重试即可。
- 源画面尺寸改变：预览自动适配，当前录像结束；恢复稳定尺寸后重新录制。
- 重复画面超过 5 秒：提示“可能正常静止，也可能停帧”。
- 录像采用 10 FPS MJPG AVI，无声音；帧可能按时间补重复帧。JSONL 记录每个视频帧对应的
  源帧编号／采集时间，便于识别重复帧。UI 延迟超过 2 秒时停止录像，不补一长段伪连续画面。
- 奇数宽高的录像会在右／下补黑边至偶数尺寸，避免编码器静默裁掉原图边缘；元数据记录两种尺寸。
- 停止采集会关闭自己的采集子进程；不会结束微信或小程序进程。

## 对照验证清单（真实小程序尚待人工验收）

分别测试 WGC／PrintWindow／屏幕区域，并记录截图、后端、窗口大小与 Windows 缩放：

- 正常显示：从静态菜单切换到有动画的页面，确认帧号／画面更新。
- 移动窗口：截图目标跟随位置。
- 调整大小／缩放：预览适配，尺寸改变时录屏正常收尾。
- 遮挡：用另一窗口部分遮住目标，检查 WGC／PrintWindow 是否仍能取得目标画面；
  屏幕区域出现遮挡内容属于该后端预期限制。
- 最小化／关闭：程序停止，恢复后可重新选择和开始。
- 保存 PNG 和短 AVI，用系统图片查看器／播放器检查文件可读。

第一批规则材料优先采集：开局到庄家首次弃牌、全部 PASS 后的摸打、剩约 20 张到结算。
请只录本人有权查看的游戏画面。自动化连接与实时识别不是本验证器的功能。

## 开发验证

```text
.venv-capture\Scripts\python.exe -B -m unittest workspace.vision.capture_validator.test_capture -v
.venv-capture\Scripts\python.exe -B -m workspace.vision.capture_validator.app --demo
```

`--demo` 只显示带 SYNTHETIC 标记的合成画面，用于人工检查 UI／录屏；不连接真实窗口。
自动测试覆盖黑屏／静止区分、尺寸变化、队列上限、图片往返、AVI 解码、时间线与异常收尾。
本次会话没有原生桌面控制通道，因此不声称已验证真实小程序的画面或遮挡表现。

WGC API 来源：[windows-capture Python 文档](https://github.com/NiiightmareXD/windows-capture/tree/main/windows-capture-python)。
独立依赖固定在 requirements.txt；启动器不会接管全局 Python 环境。

本机验证：9 项自动测试通过，包含已安装 WGC Frame 的颜色转换、带行填充缓冲区的复制、实际 PNG 往返和 MJPG AVI 解码；`pip check` 通过。
已根据用户实测修复 WGC 的 `to_bgr` 属性错误：windows-capture 2.0.1 实际接口为 `convert_to_bgr()`，并在回调内复制像素以避免原生缓冲区复用影响图像。
沙箱外 Tcl 8.6.12 初始化成功。用户反馈屏幕区域可用；修复后的 WGC 真实小程序采集仍待复测，PrintWindow 尚未确认可用。
