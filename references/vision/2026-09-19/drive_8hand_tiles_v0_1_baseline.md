# Vision V0.1 — 8局真实录像首轮基线

日期：2026-09-19（Asia/Shanghai）

## 数据来源

- 目标房完整8局回放，共8段：3/4/5/9/10/11/12/13.mp4。
- 两种真实录像分辨率：1046×480、960×448。
- 自动抽帧与近重复筛选后保留379个关键帧，生成1137个 hand/draw/gold ROI 裁剪。
- 首批人工审核标签168个，来自8个独立录像 session，覆盖34/42个牌类。
- 标签区域统计：hand 127、draw 33、gold 8。
- 原始视频、关键帧和ROI图片不提交公开仓库；本报告只记录匿名化统计结果。

## 严格评测口径

所有真实基线采用：

1. `source_session > source_frame > image` 分组；同一录像的相邻帧绝不能跨训练/测试。
2. 牌面准确率采用 `same_region + leave-session-out`；hand / draw / gold 不互相借模板。
3. 空槽先做牌面存在检测；没有可信亮色麻将牌主体的槽位不生成任意 tile_id。
4. 当前目标房的 hand / draw / gold 都属于正面可见的 `tile` 区域。
5. 所有结果继续 `safe_for_executor=false`。

## Gold 事实纠正

此前把左侧黄色高亮牌误判为“牌背 marker”是错误的。

用户补充截图清楚显示：左侧黄色框内是**正面可见的金牌**，例如截图中可直接读为4筒；手牌中的同牌也带黄色高亮。当前目标房因此采用：

```text
gold_region
  -> 直接识别正面牌面
  -> 输出 gold_id
  -> 可用多帧投票提高稳定性
```

`marker` 模式仅保留给未来其他确实只有图标/牌背的布局，不用于当前目标房。

当前8局已有8个gold人工标签，但这些gold类别尚未在至少两个独立录像session中形成同类重复，因此在严格 same-region + leave-session-out 下 **gold目前0个可评分样本**。这表示“泛化准确率暂不可测”，不是“看不到gold牌面”。

## 归一化前严格基线

在修正 source_session 泄漏并使用 same-region 后，当前可评分样本来自 hand + draw：

| 区域 | 可评估 | 精确牌面准确率 |
| --- | ---: | ---: |
| hand_region | 126 | 93.65% |
| draw_region | 25 | 68.00% |
| gold_region | 0 | 暂不可评估 |
| hand+draw合计 | 151 | 89.40% |

类别准确率98.01%。

## 牌面主体归一化

draw ROI 常带较多深色桌面/UI边缘。新增预处理：

- 灰度阈值找亮色区域；
- 3×3闭运算；
- 取最大可信亮色连通块；
- 只有面积和尺寸达到牌面门槛才认为槽位有牌；
- 裁到牌面主体后统一缩放到48×72，再做模板特征；
- 空槽直接跳过。

该变化不增加训练数据，也不改 leave-session-out 口径。

## 归一化后正式 strict baseline

| 区域 | 可评估 | 精确牌面准确率 |
| --- | ---: | ---: |
| hand_region | 126 | **95.24%** |
| draw_region | 25 | **100.00%** |
| gold_region | 0 | 暂不可评估 |
| hand+draw合计 | 151 | **96.03%** |

- 可评估覆盖率：151 / 168 = 89.88%
- 类别准确率：**98.68%**
- 置信阈值0.80：127 / 151 被接受（84.11%覆盖），接受样本精确准确率 **98.43%**
- hand：107 / 126 被接受，接受样本准确率 **98.13%**
- draw：20 / 25 被接受，接受样本准确率 **100%**
- 置信阈值0.90时，保留样本的精确准确率约98%。

剩余已观察错误集中在 hand_region，主要包括 P2↔S2、P4↔P2、M8→M2、S4→S3 等相似牌面。

## Presence-aware 连续帧稳定性

旧稳定性统计会对空 draw 槽也强行生成预测，因此不能作为门槛。加入牌面存在检测后，在8段视频相同的9.5s–10.4s固定窗口复核：

- hand：127 / 128 稳定 = **99.22%**
- draw：该固定窗口中只有2段视频真正持续出现摸牌，2 / 2稳定 = **100%**；样本量太小，不能单独作为最终门槛。
- hand+draw tile槽合计：129 / 130稳定 = **99.23%**
- gold在本轮纠正后应按tile重新建立跨session准确率与时间稳定性；不沿用此前错误的marker persistence数字。

后续使用 `mine_stability_sequences.py` 从整段录像自动挑“牌持续可见、相邻视觉低变化”的序列，扩大时间稳定性样本。

## 公开比赛状态识别

用户进一步确认：两侧玩家面板均为“头像 + 头像下方当前分数”。

正确拆分方式：

- 头像/昵称：**不做身份识别**，只作为玩家面板定位锚点。
- 双方当前分数：读取头像下方数字，写入 PublicState；与 `MatchScoreState` 交叉验证。
- 目标房2人8局双方1000分起步，正常零和结算下当前总分应保持2000，可作为OCR/状态同步的强约束。
- 同一公开状态层后续还应读取：剩余牌数、当前第几局/8、庄位/连庄相关可见字段。
- 房间号只用于调试和证据定位，不进入AI策略特征。

比分OCR属于 PublicState V0.1，不和麻将牌分类器混成同一模型。

- 仍需要不同录屏批次、窗口缩放/移动/遮挡作为外部验证集。
