### 重要口径修正

最初试跑曾按单帧 `source_frame` 留组，draw_region 的相邻帧可能来自同一段录像，存在同录像泄漏。当前正式基线改为：

1. **优先按 `source_session`（整段录像）留出**，同一视频的所有帧必须属于同一 session；
2. **默认用 `same_region` 模板池**，hand / draw / gold 不互相借模板，避免把 UI 渲染域差异混进识别门槛。

GitHub 评测代码已改为 `source_session > source_frame > image` 的分组优先级。

## 正式首轮基线：same-region + leave-session-out

在严格口径下：

| 区域 | 标签总数 | 可评估 | 精确牌面准确率 | 0.80阈值接受样本准确率 |
| --- | ---: | ---: | ---: | ---: |
| hand_region | 127 | 126 | 93.65% | 96.58% |
| draw_region | 33 | 25 | 68.00% | 80.95% |
| gold_region | 8 | 0 | 暂不可评估 | 暂不可评估 |
| 合计 | 168 | 151 | 89.40% | 94.20% |

- 可评估覆盖率：151 / 168 = **89.88%**
- 类别准确率（万/筒/条/字/花大类）：**98.01%**
- 置信阈值 0.80 时：138 / 151 被接受（**91.39%** 覆盖）
- 被接受样本精确准确率：**94.20%**
- 置信阈值 0.90 时：100 / 151 被接受（66.23%），精确准确率 **98.00%**

gold_region 不是“0%准确率”，而是当前严格评测下**无法建立独立泛化准确率**：这8局的8张金牌各自只在一个录像 session 出现，同一区域没有第二个独立 session 的同类金牌训练样本。

## 跨区域模板池诊断

为了诊断 UI 域差异，另跑 `all_regions + leave-session-out`。该结果**不作为 Executor 门槛**：

- overall：81.33%
- hand_region：92.91%
- draw_region：54.84%
- gold_region：0%
- 类别准确率：94.58%

这说明把 hand / draw / gold 混在同一个模板池会明显伤害 draw，并让 gold 被其他区域或其他金牌样式强烈干扰。

## 连续帧稳定性

从每段录像 9.5s–10.4s 取 10 个连续帧，按当前模板分类器检查 `region+slot` 一致率；稳定门槛为至少3帧且多数票一致率≥0.80。

- 总槽位序列：144
- 稳定：142
- 整体稳定率：98.61%
- hand_region：127 / 128 = 99.22%
- draw_region：7 / 8 = 87.50%
- gold_region：8 / 8 = 100%

**稳定不等于准确。** gold 在时间上可以非常稳定，但严格跨 session 泛化目前尚不可测；跨区域模板池诊断甚至会稳定地认错。因此多帧一致性不能单独作为 Executor 开启条件。

## 当前主要问题

1. **gold_region 缺独立同类样本。** 每局金牌固定，当前8局恰好没有同一金牌类别跨两个独立 session 重复；应补更多完整对局，优先等重复金牌自然出现。
2. **draw_region 仍显著弱于 hand_region。** same-region 严格基线只有68%，需要做牌面主体归一化、空白边缘处理或独立模型。
3. hand_region 已达到首轮可用水平，但仍有少量 P2/S2、M8 等混淆，不能直接视为生产门槛。
4. 仍缺6张花牌与 S7/S9；F2/F7 只有单 session。
5. 数据主要来自同一场8局，仍需不同录屏批次、窗口缩放/移动/遮挡作为外部验证集。

## 下一步

- 所有新标注写入 `source_session`，同一录像的全部帧共用同一 session ID。
- 优先改善 draw_region，再按同一 strict leave-session-out 口径复测。
- 继续从新增完整对局补 gold_region 的跨 session 重复类别；在此之前不报告 gold 泛化准确率。
- 补齐 S7/S9 与花牌覆盖。
- 增加独立录屏批次、缩放、移动和遮挡压力测试。
- 只有“跨 session 准确率 + 多帧稳定性 + 典型混淆 + 后处理约束”共同达到门槛后，才讨论 Executor。

所有当前输出继续固定 `safe_for_executor=false`。
