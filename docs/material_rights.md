# Code and visual-material rights

The repository does not currently grant an open-source license. Public access
and a clone instruction do not establish unrestricted reuse rights.

Game screenshots, cropped tile templates and code must be treated separately.
Recording or cropping a client does not establish ownership of the client's
artwork. Existing dataset labels record technical evidence, not a redistribution
license. No blanket authorization for these visual assets has been verified in
this audit, and this document does not assert that every image is infringing.

Before adding or redistributing visual material, record its source, ownership,
permission scope and permitted uses. Private raw recordings must remain outside
this public repository. Prefer original, independently authored synthetic assets
for public software examples; retain source-locked real tests privately when
rights are unresolved.

Code license selection requires the owner's decision and an assessment of
third-party contributions. Any future code license must explicitly distinguish
third-party visual material rather than silently licensing it as project-owned.
A history cleanup requires a separate reviewed migration plan: backup private
regression material, replace required fixtures, update references and coordinate
branches before rewriting history. Deleting a file from HEAD alone does not
remove historical copies. This maintenance change does not rewrite history.
